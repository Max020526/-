# NEXORA V1.0 第二阶段：商品运营与发布

第二阶段在第一阶段统一组织、RBAC、商品、SKU、库存和媒体基础上增量开发，没有重建平行商品表，也没有把库存写入混入商品编辑器。

## 已完成范围

- 商品运营工作台：草稿、资料完善中、待发布、发布受阻、已发布、已归档队列。
- 统一 SPU 多语言字段：中文、意大利语、英语名称、简短描述、详细描述与 SEO 字段。
- 颜色/尺码 SKU 管理；商品运营仅修改 SKU 主数据与渠道可见性，不直接写库存。
- 私有商品媒体：上传前压缩、10MB、JPG/PNG/WEBP、组织路径、主图、排序、软删除和审计。
- 正式渠道和价格模型：`channels`、`price_books`、`price_book_items`。
- 渠道发布模型：`product_publications`，同一商品可针对多个渠道独立验证、发布和下架。
- 发布检查：中文名称、分类、中文描述、Slug、主图、可售 SKU、当前有效渠道价格和渠道状态。
- 批量设置推荐、分类和归档；归档会下架渠道记录但不删除商品或库存事实。
- Storefront 安全投影：仅公开已发布商品、已启用 SKU、当前价格与不含存储路径的媒体元数据。
- 媒体公开地址通过服务端短期签名跳转，不把私有 Storage 路径作为商城字段。
- 所有商品、SKU、媒体、价格与发布写入使用受控 PostgreSQL Function / RPC 并写审计日志。

## 权限与边界

- Product Operator：商品资料、SKU、媒体、渠道价格、验证和发布；不能直接写库存余额或流水。
- Warehouse 角色：库存和入库作业；不能修改渠道价格或发布状态。
- 匿名用户：只能通过发布 RLS 和 `storefront_*` 安全投影读取已发布字段。
- Storage Bucket 保持 Private，匿名用户没有对象列表和私有路径访问权限。
- 旧 `save_catalog_product`、`publish_product`、`unpublish_product` 的认证执行权限已撤销，避免绕过第二阶段工作流。

## 已知限制

- 本阶段不提供完整顾客商城、购物车、支付或订单履约。
- 渠道调度记录已支持 `scheduled`，但自动定时发布任务尚未实现。
- 图片软删除后的 Storage 删除失败会提示进入清理队列；自动清理任务留待运维阶段。
- Supabase 控制台的泄露密码保护仍需手动开启，代码不能代替账户所有者变更该项目设置。
