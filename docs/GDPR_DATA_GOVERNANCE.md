# GDPR 与数据治理基线

本文件是产品运行基线，不构成法律意见。正式上线前由意大利/欧盟合资格顾问确认隐私告知、Cookie、处理依据、DPA 与保留期限。

## 数据分类与最小化

- 账户：邮箱、姓名、角色、登录审计；用于认证与授权。
- 客户：联系人、地址、订单与售后；仅为履约、客服、法定义务所需。
- 经营：商品、库存、采购、付款、财务流水；按商业与税务义务保留。
- 媒体：商品图片、到货扫描；禁止上传身份证件、银行卡、无关人像或敏感信息。

不存储银行卡完整号/CVV。真实支付必须交给合规支付服务商。日志不得记录密码、token、secret、完整支付资料或不必要的个人内容。

## 权限与处理原则

- 按组织与岗位最小权限访问；匿名仅可读取已发布商城投影。
- 高权限账号启用 MFA，不共享账号；离职账号立即停用并撤销会话。
- 数据导出只给授权岗位，导出文件带访问期限并安全删除。
- Storage 使用 private bucket、组织路径和 MIME/大小限制。

## 数据主体请求

收到访问、更正、删除、限制或可携带请求后：登记身份核验、请求时间、数据范围、法律保留例外、执行人和完成时间。删除不能破坏库存、财务、税务或反欺诈审计；需要保留时应限制处理或匿名化，并向申请人说明依据。

## 保留与删除建议

正式期限由法律顾问/会计确认。系统配置应区分：安全日志、未完成购物车、客户账户、订单/付款/退款、法定财务资料、商品媒体、到货扫描。到期删除使用受控作业，先生成待删清单，双人审核，再删除 Storage 对象和数据库元数据，记录不可含原始敏感内容的删除审计。

## 事件响应

1. 立即限制受影响凭证/账号/接口，保留日志。
2. 确认数据类别、人数、时间范围、可利用性和跨境处理。
3. 由数据负责人和法律顾问判断监管机构/数据主体通知义务及时限。
4. 轮换 secret，修复策略，验证 RLS/Storage，再恢复服务。
5. 留存决策、通知、修复和复盘记录。

## 上线前清单

- 隐私政策、Cookie/分析策略、处理依据、DPA、子处理者和跨境机制已确认。
- 数据导出/更正/删除流程完成 UAT。
- 备份、Storage、日志和 CSV 导出具有相同的数据保护级别。
- 已定义数据负责人、事件联系人和请求处理渠道。
