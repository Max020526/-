# 服装快速入库与商品上架系统实施计划

## 现状与兼容原则

现有 NEXORA 已包含入库端、管理端、库存、商品、Supabase、Storage、RLS、PWA 和独立顾客网站。新需求将采用增量迁移，不删除现有页面、迁移或线上功能。数据库中的现有 `stock_receipts`、`inventory`、`products` 等数据会在第2阶段通过兼容视图、补充字段或受控迁移接入新流程。

## 开发阶段

1. 基础结构：固定依赖，补齐浏览器、服务端和管理员 Supabase 客户端，环境变量、Netlify 构建配置和领域类型。
2. 数据库：补齐两级角色、标准状态、颜色字典、入库表、索引、触发器、RLS、Storage 策略和初始化数据。
3. 身份权限：员工与管理员登录、会话刷新、停用检查、页面和服务端双重鉴权。
4. 快速入库：款号、颜色、数量的移动端表单和单事务确认函数。
5. 批量入库：Excel 式录入、复制粘贴、重复合并、预验证和原子提交。
6. 今日入库：列表、明细、确认结果和管理员反向取消。
7. 商品主档：搜索筛选、详情、价格、分类、描述、尺码与上架检查。
8. 图片：拍照、多图、压缩、主图、排序、删除与 Storage 权限。
9. 库存：可售计算、低库存、流水和必须填写原因的修正。
10. 仪表盘：今日到货、待完善、待上架、低库存与最近操作。
11. 设置：颜色、分类、供应商和员工管理。
12. 导出与错误：UTF-8 BOM CSV、中文错误映射、权限复核。
13. 移动端与 PWA：触控、键盘流、重复提交保护、离线提示。
14. 验收与部署：全量测试、并发测试、README、Supabase 与 Netlify 上线清单。

## 第一阶段完成标准

- 现有功能和路由保持可用。
- Supabase 包使用固定版本并提交锁文件。
- 浏览器只使用 Publishable Key。
- 服务端用户客户端使用 Cookie 会话和 RLS。
- 管理员客户端只能从服务端模块读取 Secret Key。
- `.env.example` 不包含真实密钥。
- Sites 与 Netlify 分别有独立构建入口。
- `lint`、`typecheck`、Sites 构建和 Netlify 构建均成功。

## 第二阶段完成标准

- 现有业务表和数据不删除，新增快速入库兼容表与标准字段。
- `employee` / `admin` 与旧角色安全映射，商城顾客保持隔离。
- 快速入库表启用 RLS，库存表禁止客户端直接写入。
- 26 个标准颜色代码、基础分类与 `ONE_SIZE` 可重复初始化。
- 每日入库编号由数据库原子生成，并通过格式、唯一性与回滚验证。
- 线上 Supabase 迁移、类型生成、Advisors、lint、typecheck 和构建均通过。
