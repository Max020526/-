## 3. P01 入库流程

入库不是两套业务，而是同一工作区的两种录入模式：

1. **快速入库**：已经人工核对款号、颜色、数量时使用。员工录入后调用 `confirm_inbound_order()` 原子创建或匹配商品、SKU、库存、入库明细、库存流水和审计日志。
2. **OCR / 货单入库**：存在供应商货单、表格或照片时使用。流程为创建货单、识别、人工复核、实收、异常处理、调用 `confirm_stock_receipt()` 过账。
3. 两种模式最终进入 `/warehouse/receipts`，使用相同统计、查询和导出口径。
4. 管理员随后在 P02 商品运营补充图片、价格、描述和分类，通过发布检查后上架。

## 4. 端到端业务流程

```text
供应商/新货
  → P01 入库（快速或货单模式）
  → 共享商品、SKU、库存流水
  → P02 商品完善与发布
  → C01 零售网站 / 未来 C02 批发门户
  → P03 订单与客服
  → P04 仓库履约
  → P06 收款、退款与对账
  → P07 经营分析
```

退货退款遵循：P03 审核 → P06 退款记录 → P04 实物质检 → 可售商品重新入库或破损报废 → 全程审计。

## 5. 数据与权限原则

- 商品、SKU、库存、订单均只有一个主数据来源，不在不同前端复制。
- 员工端不维护成本、售价、发布状态或系统权限。
- 管理端可查看和配置经营数据，但库存变化必须通过受控 RPC 并填写原因。
- 高风险写入使用数据库事务、幂等键、行锁和审计日志。
- 所有业务表启用 RLS；页面隐藏不能替代数据库授权。
- 规划中入口只说明边界，不产生模拟数据，不在验收前伪装为可用模块。
