# 安全与性能审计记录（2026-08-01）

## 已修复

- 修复共用 Supabase 查询 Hook 因内联初始数组引用变化产生的重复请求循环，并加入过期响应隔离。
- 将 `/catalog` 与 `/me` 纳入内部会话代理保护范围。
- 加固员工管理 API：服务端管理员校验、同源校验、JSON 与 8KB 请求限制、字段长度、UUID 校验、禁止管理员自我降权、禁止缓存。
- 内部登录入口停止提供顾客注册；顾客使用独立商城，内部账号由管理员创建。
- 两种部署链路统一 CSP、HSTS、点击劫持、MIME 嗅探、浏览器权限、COOP 与 DNS 预取安全头。
- 商品图片与 OCR 图片增加像素上限，释放本地预览 URL，删除图片时优先保证数据库不产生失效引用。
- 新增安全与性能契约测试，防止上述保护在后续修改中退化。

## 已验证

- npm 生产依赖审计：无已知漏洞。
- Supabase 业务表：均启用 RLS；库存不允许浏览器直接更新；高权限函数不开放给匿名角色。
- 数据库锁与慢查询：未发现业务死锁；现有数据量下无异常慢业务 SQL。
- 线上日志：重复商品读取来自前端 Hook，根因已修复。

## 仍需平台侧完成

- Supabase Auth 的泄露密码检测需要在 Dashboard 的 Authentication 安全设置中启用；此项不能通过当前数据库迁移代替。
- 正式开放互联网前，建议为内部管理员启用 MFA，并接入错误监控与真实手机回归测试。
