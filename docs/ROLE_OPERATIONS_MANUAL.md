# 岗位操作与职责边界

所有人从统一主页选择工作区；端口只是职责入口，不是独立数据系统。不得共享账号。

| 岗位 | 日常入口与动作 | 明确禁止 |
| --- | --- | --- |
| Owner | 经营看板、最终审批、用户/设置、重大库存与退款决策 | 不直接改库存表或审计记录 |
| System Admin | 账号、角色、系统配置、技术排障 | 不代替业务岗位确认到货/付款 |
| Warehouse Manager | 到货审核、确认入库、库存调整审批、履约异常 | 不改价格、财务分录 |
| Warehouse Staff | 点货、快速录入、实收核对、拣货/复核/打包 | 不确认越权入库、不改库存余额 |
| Product Operator | 商品资料、图片、SKU 可见性、发布检查、上下架 | 不直接增加库存、不审批采购付款 |
| Order & CS | 订单核验、取消、售后申请、客户沟通记录 | 不直接退款入账、不绕过退货质检 |
| Buyer | 供应商、采购草稿、采购提交、采购差异跟进 | 不确认仓库实收、不改财务流水 |
| Finance | 费用、采购付款、收退款核对、经营报表导出 | 不改已生成财务流水，不替代法定会计 |
| Cashier | POS 开班、扫码销售、收款、关班与现金差异 | 不改商品成本/库存、不删除销售 |
| Auditor | 审计、库存/财务只读检查与导出 | 不执行业务写操作 |

## 仓库标准流程

1. 创建到货单，选择供应商、单号、日期；同款可连续添加多颜色/尺码。
2. 保存草稿并检查总款数、SKU 数、件数；错误行必须先修正。
3. 提交点货，按实物填写实收数量，差异不得隐藏。
4. 有权限人员确认入库；等待成功回执后才能离开，不要重复点击。
5. 错误入库不得删除；由管理员填写原因并走反向流水/调整流程。

## 商品运营流程

待补充商品依次完成主图、名称、分类、零售价、描述、可售 SKU 和库存检查。发布前使用上架检查；发布后商城只读取公开投影。修改 SKU 需二次确认并审计。

## 订单与售后流程

订单、付款、履约是独立状态。客服只能发起允许的状态命令；仓库逐行复核后发货/交付才扣在手库存。取消释放预留。退货先审核、收货、质检，再按可售/隔离/破损/报损处置；退款状态不代表支付网关真实清算。

## 异常升级

- 发现重复入库/订单、负库存、越权可见、金额不一致：立即停止相关操作并通知 Owner/System Admin。
- 保留单号、时间、账号、截图和 request/idempotency key；不得删除记录“修复”。
- 网络中断后先查询单据状态再重试，不能凭页面提示推断数据库未保存。
